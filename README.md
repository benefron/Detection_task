# Whisker-Generated Sound Detection Task

A complete closed-loop behavioral neuroscience system for training and testing head-fixed mice in a tactile object detection task, based on acoustic signals generated by whisker-object contact.

> **Associated Publication:**
> **Detection and neural encoding of whisker-generated sounds in mice**
> Ben Efron, Athanasios Ntelezos, Yonatan Katz, Ilan Lampl
> *Current Biology*, 2025
> [https://www.cell.com/current-biology/abstract/S0960-9822(25)00124-1](https://www.cell.com/current-biology/abstract/S0960-9822(25)00124-1)

Developed as part of a PhD in Systems Neuroscience at the **Lampl Lab, Weizmann Institute of Science** (Prof. Ilan Lampl).

---

## Overview

Mice use their whiskers to actively explore and identify objects. When a whisker brushes against a surface, it generates brief acoustic transients. This system implements a **go/no-go detection task** in which head-fixed mice learn to detect and respond to these whisker-generated sounds.

The full experimental pipeline was designed and built from scratch, including:

- **Real-time behavior control** via [Bonsai](https://bonsai-rx.org/) reactive programming
- **Custom motor firmware** for two Teensy 4.0 microcontrollers (object selection + whisker contact delivery)
- **Automated stimulus delivery** with randomized object positioning to prevent prediction
- **Synchronized data acquisition** — behavioral events, video, and ultrasonic audio
- **Post-session analysis** in MATLAB and a custom Python/PyQt5 GUI with d-prime metrics

---

## Scientific Context

The core question driving this work is: **do mice detect objects through the sounds their whiskers generate, rather than through direct tactile contact?**

The task is designed to test this by:
1. Training mice to lick for a water reward when presented with an aluminum foil object (strong acoustic signal on whisker contact)
2. Withholding reward for an acoustically attenuated object (same physical contact, reduced sound)
3. Measuring detection performance using signal detection theory (d-prime)

By comparing hit rates and false alarm rates across stimulus conditions, the task quantifies whether mice are responding to the acoustic component of whisker contact.

                            │ Firmata / Serial
               ┌────────────┴───────────┐
               │      Teensy 4.0 #1     │
               │    (Firmata bridge)    │
               └────────────┬───────────┘
                            │ Serial commands
               ┌────────────┴───────────┐
               │      Teensy 4.0 #2     │
               │   (Motor controller)   │
               │  ┌──────────────────┐  │
               │  │  Stepper Motor   │  │
               │  │ (Object rotation)│  │
               │  ├──────────────────┤  │

               │  │ (Whisker contact)│  │
               │  └──────────────────┘  │
               └────────────────────────┘

**Hardware components controlled:**
- **Stepper motor** — rotates a multi-object holder to select between aluminum foil, attenuated object, or no object
- **Linear motor** — advances the selected object to whisker-contact distance
- **Solenoid water valve** — delivers sucrose water reward on correct responses
- **Capacitive lick sensor** — detects lick responses in real time
- **Speaker** — plays white noise during catch conditions
- **Camera** — records whisking behavior for offline analysis
- **Avisoft USGH** — captures ultrasonic audio synchronized to trial events

## Local Configuration

Before running the system on a new PC, three machine-specific settings in `Behivior_new.bonsai` must be updated:

| Setting | Location in workflow | Default value | What to set |
|---------|----------------------|---------------|-------------|
| **Data path** | `Path` parameter in the main window | `E:\Ben\Omer training` | Local directory where animal folders will be saved |
| **Teensy #1 COM port** (Firmata bridge) | Arduino/Firmata serial nodes | `COM9` | COM port assigned to the Firmata Teensy on this PC |
| **Teensy #2 COM port** (Motor controller) | Serial-port nodes for motor commands | `COM15` | COM port assigned to the motor Teensy on this PC |

To find the correct COM ports, open **Device Manager → Ports (COM & LPT)** while the Teensy boards are connected. Update the values in the workflow and save before starting acquisition.

## Task Design

### Training Levels

| Level | Name | Description |
|-------|------|-------------|
| 0 | Lick training | Reward is delivered for any lick at the water port |
| 1 | Go/No-Go | Mouse must lick for the rewarded stimulus; false alarms trigger a timeout |
| 2 | Object detection | Discrimination between aluminum foil and acoustically attenuated object |
| 3 | Test phase | Full detection task with attenuated objects; validates learned detection behavior |

### Stimuli

| Stimulus | Acoustic signal | Expected response |
|----------|-----------------|-------------------|
| Aluminum foil | Strong (clear whisker-generated sound) | Lick (Go) |
| Attenuated object | Reduced or absent | Withhold (No-Go) |
| Catch trial | None (motor stops short of contact) | Withhold (No-Go) |

### Key Configurable Parameters

| Parameter | Description |
|-----------|-------------|
| `Difficulty` | Binomial probability of rewarded stimulus presentation (0.5 = fully random) |
| `P2I` | Fraction of trials where reward is given regardless of licking (instructed trials) |
| `Catch trial %` | Fraction of trials where motor stops short of whisker contact (default: 10%) |
| `Reward time` | Solenoid open duration, calibrated to µL |
| `Time out` | Penalty interval after an incorrect response (seconds) |
